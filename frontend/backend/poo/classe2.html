POO JavaScript Completo

Programação Orientada a Objetos explicada de forma simples.

O que é POO?

POO significa: Programação Orientada a Objetos

A ideia é representar objetos do mundo real dentro do código.

Exemplo:

  • Carro
  • Cliente
  • Conta Bancária
  • Animal
  • Usuário

Classe

Classe é um molde.

Ela define:

  • dados
  • atributos
  • métodos

Exemplo: A classe Carro define como os carros serão.

class Carro { constructor(){ } }

Objeto

Objeto é a criação real da classe.

Exemplo:

const carro1 = new Carro();

Agora carro1 é um objeto.

Instância

Instância é o objeto criado pela classe.

const bmw = new Carro();

A BMW é uma instância da classe Carro.

Classe Completa

class Carro { // constructor = construtor // executa ao criar objeto constructor( marca, modelo, combustivel ){ // atributos this.marca = marca; this.modelo = modelo; this.combustivel = combustivel; this.ligado = false; this.velocidade = 0; } // método ligar(){ this.ligado = true; return this.modelo + " ligou."; } acelerar(){ this.velocidade += 10; return this.modelo + " acelerou para " + this.velocidade + " km/h"; } parar(){ this.velocidade = 0; return this.modelo + " parou."; } }

4 Pilares da POO

1. Abstração

Mostrar apenas o necessário.

Você dirige o carro sem saber como funciona o motor internamente.

2. Encapsulamento

Proteger dados internos.

Evita alterações erradas.

3. Herança

Uma classe pode herdar de outra.

4. Polimorfismo

Mesmo método pode ter comportamentos diferentes.

Encapsulamento

Usamos # para atributo privado.

class Conta { #saldo = 0; depositar(valor){ this.#saldo += valor; } verSaldo(){ return this.#saldo; } }

Não pode acessar:

conta.#saldo

Herança

class Veiculo { ligar(){ return "Veículo ligado"; } } class BMW extends Veiculo { } const carro = new BMW();

BMW herdou os métodos de Veiculo.

Polimorfismo

class Animal { emitirSom(){ return "Som genérico"; } } class Cachorro extends Animal { emitirSom(){ return "Au Au"; } } class Gato extends Animal { emitirSom(){ return "Miau"; } }

Mesmo método: emitirSom() Mas comportamentos diferentes.

Interface

JavaScript puro não possui interface real como Java ou C#.

Mas podemos simular.

class InterfaceCarro { ligar(){} acelerar(){} parar(){} abastecer(){} trocarPneu(){} }

Toda classe carro deveria implementar esses métodos.

Exemplo Completo Carros

class Carro { constructor( marca, modelo ){ this.marca = marca; this.modelo = modelo; this.ligado = false; this.combustivel = 100; } ligar(){ this.ligado = true; return this.modelo + " ligado."; } acelerar(){ return this.modelo + " acelerando."; } dirigir(){ return this.modelo + " dirigindo."; } parar(){ return this.modelo + " parado."; } abastecer(){ this.combustivel = 100; return this.modelo + " abastecido."; } trocarPneu(){ return this.modelo + " pneu trocado."; } } class BMW extends Carro { } class Uno extends Carro { } class Gol extends Carro { }

SOLID

S - Single Responsibility

Cada classe deve ter uma única responsabilidade.

O - Open Closed

Aberto para extensão, fechado para modificação.

L - Liskov

Classe filha deve substituir a classe pai sem quebrar sistema.

I - Interface Segregation

Interfaces pequenas são melhores.

D - Dependency Inversion

Depender de abstrações, não implementações.

GOF - Design Patterns

GOF significa: Gang of Four

São padrões de projeto.

Singleton

Apenas uma instância.

Factory

Classe cria objetos.

Observer

Observa mudanças.

Strategy

Troca comportamento.

Exemplo Factory Pattern

class FabricaCarro { criarCarro(tipo){ if(tipo === "BMW"){ return new BMW( "BMW", "X6" ); } if(tipo === "UNO"){ return new Uno( "Fiat", "Uno" ); } } }

Exemplo Singleton

class BancoDados { static instancia; constructor(){ if(BancoDados.instancia){ return BancoDados.instancia; } BancoDados.instancia = this; } }

Garante apenas 1 instância.
